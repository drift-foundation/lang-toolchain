Summary: Single-entry module import resolution unclear + parser rejects return in match-arm block expression

 1. Module resolution in single-entry compile

  // a.drift
  module a
  import b as b;
  fn main() -> Int { return b.answer(); }

  // b.drift
  module b
  pub fn answer() -> Int { return 42; }

  - Repro command (single entry only):
    driftc a.drift
  - Observed:
    imported module 'b' not found
  - Expected:
    Either:

  1. imports in same directory/package are resolved automatically, or
  2. compiler emits a clear diagnostic requiring explicit package/module root flag.
  3. Parser behavior for return in match arm expression block

  - Minimal repro:

  import std.core as core;

  fn f(r: core.Result<Int, Int>) -> core.Result<Int, Int> {
    val x = match r {
      Ok(v) => { v },
      Err(e) => { return core.Result::Err(e); }
    };
    return core.Result::Ok(x);
  }

  - Repro command:
    driftc repro.drift
  - Observed:
    Parser error near } in the Err arm.
  - Expected:
    Either:

  1. allow return in block expression used by match arm, or
  2. produce targeted diagnostic stating return is not valid in this expression context.
