pre-existing, but repository policy and Slawomir's standing direction require
pre-existing compiler bugs discovered during the work to be fixed rather than
left as optional follow-up.

The reviewer independently reproduced:

```text
<unknown location>:?:?: error: intrinsic CallInfo is missing source call node
[E_INTRINSIC_CALLINFO_MISSING_NODE]
```

`repro::main`: its finalized HIR contains only the outer invocation at
callsite 3, while its CallInfo table still contains the extracted lambda
body's callback/method callsites 0-2.  `_apply_fnptr_consts` removed the source
subtree, but `TypedFn` detached the enclosing function's entire side table;
the strict intrinsic validator then correctly detected the orphan.

This is now a required child finding with a repro, trace, root-path evidence,
counter-boundary analysis, proposed patch shape, and test matrix:

`findings/finding-nested-lambda-intrinsic-callinfo/`

Read that folder in full and revalidate its hypothesis.  Create its
implementer-owned `PROGRESS.md`, and list the child's status in the parent
`PROGRESS.md` per the nesting protocol.  The recommended direction is to
partition callsite-indexed tables by finalized function ownership while
preserving the LambdaFnSpec data needed before the independent re-check.  Do
not weaken `_validate_intrinsic_callinfo`; that would mask the broken

supports it.

Add the regression red-first in a new test module and include a full
