# Review: nested-lambda intrinsic CallInfo ownership

Date: 2026-08-04T21:10:15Z

Outcome: **signed off**.

The implementation fixes the demonstrated ownership mismatch at the correct
boundary.  After `_apply_fnptr_consts` finalizes the function body,
`TypedFn.call_info_by_callsite_id` and
`TypedFn.instantiations_by_callsite_id` are detached only for callsites still
reachable in that body.  The traversal intentionally descends into lambdas
that remain represented, preserving immediate-IIFE and callback-argument
consumers.  The live checker maps are not pruned, so `LambdaFnSpec`'s
pre-recheck terminal-call classification retains its input; extracted bodies
still rebuild their own tables during independent checking.

The strict reverse intrinsic validator is unchanged.  This is important: the
fix removes the orphan rather than teaching the validator to ignore it.

Coverage is proportionate and non-vacuous:

- stored lambda containing `core.callback0`, full compile/run;
- direct-parent and extracted-lambda callbacks coexisting;
- immediate-IIFE counter-boundary;
- structural assertion that both detached callsite-indexed maps contain no
  entries absent from finalized HIR, with an explicit extraction guard.
