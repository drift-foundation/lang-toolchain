## Findings

### 1. P1 — the construction-only value-capture path skips checking and can leave an uninitialized binding

**Status: the skipped authorities and absent value are confirmed statically; the exact failure surfaces of the proposed probes need execution.**

Revision 5 changes uninvoked value-capture lambdas from the prior rejection to a special construction-only route. That route is not a sound implementation of the source contract yet.

#### 1a. The body and capture requirements are never type-checked

Every unannotated `HLet` lambda is deferred before its initializer is typed at `lang/driftc/type_checker.py:12286-12299`. At the final flush, any lambda with captures enters `lang/driftc/type_checker.py:13735-13756`; after the borrow-kind diagnostic it assigns the binding `Unknown` and unconditionally continues. It never calls `type_expr(_pend_lam)`.

That skips all of the ordinary `HLambda` work at `lang/driftc/type_checker.py:7358-7975`, including:

- typing names, calls, returns, and effects in the body;
- validating `captures(copy x)` against `Copy`;
- validating `captures(share x)` against `Share`;
- typing the synthesized `share_value` call and recording its `CallInfo` (`type_checker.py:7584-7609`).

Phase 2 cannot recover this: it deliberately treats `HLambda` as an independent-function boundary and does not recurse into its body at `lang/driftc/checker/__init__.py:4617-4621`. Stage 2's special path at `lang/driftc/stage2/hir_to_mir.py:9292-9352` likewise ignores the body.

A minimal semantic probe is:

```drift
pub fn main() nothrow -> Int {
    val x = 1;
    val f = || captures(copy x) => { unknown_name };
    return 0;
}
```

On the reviewed path, `unknown_name` has no checker visitor and the lowering discards the body, so this is expected to compile silently. Companion probes should use:

- `captures(copy b)` where `b` is non-Copy;
- `captures(share x)` where `x` is Copy or does not implement `Share`;
- a valid `captures(share arc)` that needs a monomorphized `Share::share` CallInfo.

There is already a particularly important consistency check: `test_explicit_capture_copy_non_copyable_reports_driver_diag` in `lang/tests/driver/test_explicit_capture_diagnostics.py:180-197` uses this exact unannotated/uninvoked stored shape and requires the Copy diagnostic. Static routing says Revision 5 bypasses its authority, while `PROGRESS.md` reports the whole explicit-capture-diagnostics file green. K should reconcile that contradiction first. If the test really passes, identify and document the other authority that diagnoses it; none is visible on this path.

#### 1b. “Any use is rejected use-site” is an assertion, not an enforced invariant

The flush records only `binding_types[_pend_bid] = Unknown` at `type_checker.py:13755`; there is no construction-only/poisoned-binding marker. A normal value read may happen to trip the generic Unknown Copy guard, but not every use is a Copy use. In particular, explicit `HMove` types its subject with `used_as_value=False` at `type_checker.py:9678`, and `_require_copy_value` returns immediately for that mode at `type_checker.py:3999-4000`.

Probe:

```drift
pub fn main() nothrow -> Int {
    val x = 1;
    val f = || captures(copy x) => { x };
    val g = move f;
    return 0;
}
```

The source `HLet(f)` allocates the local name but the special MIR path returns without storing a value (`hir_to_mir.py:9360-9364`, `9377-9390`). Lowering `move f` can therefore reach a `MoveOut` from a local that was never initialized. Borrowing or otherwise routing the Unknown binding through a non-Copy-use position deserves the same audit. A clean diagnostic appearing later would be better than an ICE, but it would still refute the claim that one explicit authority prevents every use.

#### 1c. Binding nothing does not implement the documented closure-value contract

The current language spec says value captures may escape (`doc/design/drift-lang-spec.md:4592-4620`) and defines closure creation as evaluating captures, storing them in closure-object fields, and **producing the closure value** (`doc/design/spec-change-requests/drift-closure-explicit-captures.md:163-174`). The new lowering evaluates some captures into dropped temporaries and deliberately binds nothing. This may be observationally equivalent only after proving the source binding is unused and after type-checking every capture/body effect; neither proof currently exists.

There are two plausible closure directions, and K should not treat this review's preference as authority:

- If bare stored value-capture closures are a supported language value, lower a real representation (possibly by reusing the callback/closure machinery) and make moves/calls/drops of the stored value work.
- If the current v1 implementation intentionally supports escaping captures only through an explicit callback/Fn-bounded conversion, reject this raw stored form cleanly and reconcile the contradictory spec and `test_explicit_capture_value_escape_allowed`. Because repository rules forbid editing an existing test without confirmation, obtain the user's ruling before changing that test/contract.

A temporary third option—construction-only acceptance for a provably unused binding—would need, at minimum: ordinary no-expectation `type_expr` checking of the lambda; recorded `share_value` CallInfo/coercions; an explicit HIR/checker marker proving every use is rejected (including move/borrow); and lowering gated by that marker rather than by `isinstance(HLambda)`. It still needs an explicit language-contract justification because it creates no value for a syntactically value-producing `HLet`.

Required boundary pins depend on the chosen contract, but must cover invalid body, non-Copy copy capture, invalid and valid share capture, move/borrow/use of the stored binding, and full compile/run plus ownership/drop/ASAN behavior for owned move/share captures. A checker-only green result is insufficient.

### 2. P1 — the scheduler can leave a thunk registered by its last instantiation drain

**Status: confirmed from producer/consumer ordering; a source driver that forces the edge should be built and probe-verified.**

The quiescence loop at `lang/driftc/driftc.py:7751-7759` runs:

```python
_drain_hidden_lambda_specs()
_synthesize_thunk_specs()
_drain_instantiations()
_synthesize_late_drained_fns()
if hidden_lambda_index >= len(hidden_lambda_specs) and not inst_queue:
    break
```

`_drain_instantiations()` calls `type_checker.check_function()` for each concrete instantiation at `driftc.py:5170-5190`. That check can append a thunk through `_ensure_ok_wrap_thunk` / `_ensure_boundary_thunk` (`type_checker.py:4473-4518`). Because thunk synthesis precedes the instantiation drain, a thunk first registered during that drain remains un-emitted. If late lowering adds no hidden spec and the instantiation queue is empty, the loop's condition is immediately true and no later code calls `_synthesize_thunk_specs()` (`driftc.py` has calls only at lines 7723 and 7755).

Revision 5's `test_thunk_registered_during_drain_runs` is now honest for a thunk registered while a captureless lambda spec is rechecked. That happens before quiescence, so line 7755 sees it. It does not cover a thunk registered while line 7756 checks a concrete generic instantiation.

**Proposed closure:** make thunk completion part of the fixed-point predicate, or reorder/repeat thunk synthesis after `_drain_instantiations()`. A robust loop should compare all producer sets/indexes before and after an iteration (lambda specs, hidden specs, instantiations, thunk specs, and any late function set), rather than infer global stability from only `hidden_lambda_index` and `inst_queue`.

The new regression needs two genuinely late stages: a captureless-lambda recheck queues a concrete generic instantiation, and checking that concrete instantiation performs a function-reference coercion whose concrete signature registers a distinct thunk. K should derive the smallest accepted source spelling from the existing generic/function-reference tests and document why the thunk key did not already exist at template-check time. Inspecting `type_checker.thunk_specs()` or emitted MIR symbols in a focused unit/stub test can prove the production moment; a full compile/run companion must prove the emitted target exists.

### 3. P1 — throw-effect reachability is still eager inside lazy expressions

**Status: confirmed against HIR→MIR evaluation order; source diagnostics should be probe-verified.**

Revision 5 correctly adds `_block_can_throw` / `_stmt_can_throw` for statement CFG reachability. But `_stmt_can_throw` sends ordinary expression-bearing statements to reflective traversal at `lang/driftc/stage1/hir_flow.py:396-398`, and `_RECURSIVE_TYPES` includes `HBinary`, `HTernary`, and `HAssert`. Reflective `_can_throw` visits every child, even when lowering does not evaluate that child.

Three concrete lazy forms are missed:

- `HBinary(AND/OR)` lowers with short-circuit blocks at `lang/driftc/stage2/hir_to_mir.py:3963-3988`. A literal `false and throwing_call()` or `true or throwing_call()` never evaluates the RHS, but the effect walker counts it.
- `HTernary` lowers only the selected branch through a diamond at `hir_to_mir.py:8550-8604`. With a literal condition, one branch is dead, but the walker counts both.
- `HAssert` evaluates `msg` only in the failure block at `hir_to_mir.py:9188-9233`. `assert(true, throwing_string_call())` cannot execute the message call, but the generic statement walk counts it.

These can falsely reject an explicitly `nothrow` lambda even though executing it cannot throw. Suggested positive probes:

```drift
val a = || nothrow => { false and throwing_bool(); 0 };
val b = || nothrow => { true ? 1 : throwing_int(); };
val c = || nothrow => { assert(true, throwing_string()); 0 };
```

Each needs a live companion proving the opposite side still counts: `true and ...`, `false ? 1 : ...`, and `assert(false, ...)` (or nonliteral conditions where either route is reachable).

**Proposed closure:** add expression-specific lazy evaluation to the shared effect authority: always inspect the left/condition first, then fold only literal booleans; otherwise inspect every potentially reachable branch. Do not globally constant-fold arbitrary expressions unless lowering/checking shares that authority. Unit pins should cover the HIR forms directly, with at least one full compile/run `nothrow` companion because this decision changes lowering-visible call ABI/effect handling.
