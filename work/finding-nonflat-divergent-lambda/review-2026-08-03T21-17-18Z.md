The implementer's pause was correct. The prior review exposed a conflict in

## Approved source direction

Delete the unconditional unqualified `Ok(expr) -> HResultOk` rewrite in
`stage1/ast_to_hir.py`. Unqualified `Ok(...)` must remain an ordinary `HCall`
and flow through the existing expected-variant constructor resolver. This is
the behavior specified by §10.3:

- `val r: Result<Int, String> = Ok(1)` has a variant expectation and is a
  public `Result::Ok` construction;
- `val r = Ok(1)` has no expected variant type and is rejected rather than
  guessed;
- `return Ok(1)` is valid only when the surface return expectation is an
  appropriate variant type. A `throws -> Int` function supplies an `Int`
  expectation, not an implicit public `Result` expectation.

The production inventory supports deleting `HResultOk` itself. The AST
rewrite is the only genuine source producer; the alpha-renamer case merely
reconstructs an already-produced node, and the remaining constructors are
synthetic tests. Can-throw success wrapping is independently produced as MIR
`ConstructResultOk`, so deleting the HIR expression does not delete the
throwing ABI.

Deletion must be exhaustive. The current tree has 35 `HResultOk` references
across 12 compiler Python files, plus 9 references across 6 test files. Remove
the class, export/imports, traversals, alpha-renaming, type/effect/borrow/place
handling, Phase-5 slot handling, phase-2 inference, and HIR-to-MIR lowering.
The handback should show:

```text
rg -n --glob '*.py' '\bHResultOk\b' lang/driftc lang/tests
```

with no current code/test references. Update current comments and test prose
that describe the deleted node. Do not rewrite historical entries as if the
old implementation never existed; add a superseding history note instead.

## Approved test migrations

### 1. Phase-5 ConstShare positive

Approve replacing
`test_phase5_result_ok_payload_duplicates` with a public, context-resolved
variant-constructor test built around:

```drift
val r: core.Result<core.ConstArc<String>, Int> = Ok(a);
```

and a later use of both `a` and the `Ok` payload. Rename/rewrite the test prose
so it claims the surviving contract: an ordinary variant constructor's owned
payload slot receives implicit ConstShare duplication. It must no longer
claim coverage of an `HResultOk.value` slot.

The existing `_compile()` helper in that file uses `--test-build-only`; that
alone is not "end-to-end." Preserve both levels of evidence:

1. Structural: capture the post-typecheck HIR and assert that the `Ok` HCall's
   payload argument is an
   `HMethodCall(method_name="const_share", origin="implicit_const_share")`,
   with no bare `HVar(a)` left in the constructor argument. The capture/walk
   pattern already exists in
   `test_constshare_generic_field_frontend.py::_compile_capture` and can be
   reused or factored without inventing a second mechanism.
2. Full compile/run: construct the annotated `Result`, read `a` afterward,
   consume/match the `Ok` payload, and assert a semantic exit code. This is
   mandatory under the checker/lowering contract because constructor routing
   and ownership rewriting are lowering-visible.

### 2. Direct `return Ok(5)` negative

Approve replacing the obsolete `FnResult`-mismatch expectation in
`test_named_fn_return_ok_wrapped_rejected`, but **not** the proposed
"whichever behavior emerges" alternative.

For:

```drift
fn f() throws -> Int { return Ok(5); }
```

the expected surface type is `Int`, which is not a variant. Section 10.3 does
not permit the compiler to guess `Result<Int, E>`, infer an error type, and
immediately auto-try it. Pin one clean constructor-context rejection (prefer
the established `E-CTOR-EXPECTED-TYPE` contract), no duplicate diagnostic,
and no traceback. If the current call resolver falls through to an unrelated
"not a function" error when the expected type is non-variant, fix that source
diagnostic rather than blessing it.

Add a contrasting full compile/run positive where the return expectation is
actually a public `Result`, ideally a can-throw function returning
`core.Result<Int, String>`. `return Ok(5)` must then build the public inner
variant and receive exactly the normal outer throwing-ABI wrap; the caller
must successfully `try` the call and match the public result. This proves the
two layers are distinct and that no double-wrap payload mismatch remains.

### 3. Synthetic-node tests

Approve deleting these node-specific tests with the deleted HIR class:

- `test_checker_call_type_checks.py::test_result_ok_without_signature_type_ids_does_not_blow_up`
- `test_type_checker_expressions.py::test_result_ok_uses_fnresult_type`

Their contract is the existence/typing of the legacy node, so retaining a
compatibility stub would violate the pre-1.0 one-contract rule. Coverage of
the source failure moves to the constructor-context negative above.

### 4. Route and no-context pins

Approve editing the existing parser test file to add a direct source-shape
pin that unqualified `Ok(1)` lowers to `HCall`, not a special expression.
Also update the neighboring qualified/attribute-call comment so it does not
refer to a deleted node.

Pin the child repro's unannotated local form (`val r = Ok(a)`) as a clean
`E-CTOR-EXPECTED-TYPE`-class rejection with no traceback. This is distinct
from the annotated Phase-5 positive and directly closes the observed LLVM
ICE route.

Slawomir's approval covers the HResultOk-specific edits to the existing test
files named above, the Phase-5 file, the parser-adapter file, and stale
HResultOk-only prose in existing tests such as
`test_borrow_in_cast_no_double_free.py`. It does not authorize unrelated test
