## P1 — the bare-closure ruling has not been migrated through the existing contract surface

**Status: the source/test contradiction is confirmed statically; the exact e2e
harness output is predicted from the checker route and should be run by the
implementer.**

The checker now unconditionally rejects an unresolved bare stored value-capture
lambda at `lang/driftc/type_checker.py:13735-13764`, before typing its body or
applying capture ownership effects. That matches the user's ruling: no bare
anonymous closure value exists in v1, and value captures escape only through a
supported callback/Fn-bounded representation.

One pre-existing e2e still asserts the opposite contract:

- `lang/tests/codegen/e2e/closures_explicit_captures_move_use_after_move_rejected/main.drift:5`
  stores `captures(move x)` in a bare `val f`;
- its `expected.json:3-7` requires a borrow-checker `use after move of 'x'`.

On the new route, this source gets the binding-time type-check diagnostic
`bare capturing lambdas cannot be stored in v1`. The flush deliberately does
not type the invalid lambda or apply its move capture, so the expected
borrow-check diagnostic has no authority left to produce it. This test was not
in the reported targeted battery, and no full suite was run.

Migrate that ownership regression to a supported construction, for example a
`core.callback0(...)` value containing `captures(move x)`, while retaining the
later `return x` and the borrow-checker expectation. That preserves the useful
contract the test was meant to pin: a move capture consumes its source when the
supported callback representation is constructed, even if the callback is
never invoked. It also supplies the behavioral assertion missing from
`test_value_captures_escape_via_callback_runs` at
`lang/tests/driver/test_uninvoked_stored_lambda.py:209-223`, whose current
source constructs a callback with a move capture but never attempts to use the
moved source.

The documentation is internally inconsistent with the same ruling:

- `doc/design/drift-lang-spec.md:4507` still says every capturing lambda
  literal produces a compiler-synthesized closure value and describes
  copy/move captures as escaping. That conflicts with the contextual-only
  representation rule now stated at `:4620-4628`. Rewrite the earlier callable
  taxonomy so it says that a capturing literal may be immediately invoked or
  converted through a supported representation, but has no standalone
  anonymous value type in v1.
- `doc/design/spec-change-requests/drift-closure-explicit-captures.md:137-169`
  still makes escaping raw copy/move closures, closure-owned loans transferred
  by moving the closure, and `Produce the closure value` part of its required
  MVP model. If this file is retained as historical design input, mark those
  portions clearly superseded by the current v1 contract; otherwise reconcile
  them directly. It must not read as a second current contract.

An inventory over source-like in-tree files found the stale e2e above as the
only remaining bare `val ... = |...| captures(copy|move|share)` Drift fixture
outside the intentional new negative tests. K should repeat that inventory
after the migration rather than assuming this review's regex covered every
surface spelling.
