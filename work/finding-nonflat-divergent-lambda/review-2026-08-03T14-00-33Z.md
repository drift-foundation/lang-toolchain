# Static review: non-flat divergent lambda follow-up

Date: 2026-08-03T14:00:33Z

Verdict: changes requested. The four new compile/run probes cover the exact
if/match/nested-block cases that originally exposed the defect, and the new
`HMatchExpr` / `HBlock` descent explains the observed SIGABRT. The finding is
not closed yet: both new authorities remain partial, and the throw-effect

Static review only; no tests run.

## P1 — `_block_diverges` is another syntax whitelist, not the repository's semantic terminal-flow authority

`lang/driftc/type_checker.py:7812-7844` recognizes only a final throw/rethrow,
nested plain block, two-arm `if`, or statement-form match. It explicitly
returns `False` for loops, try/catch, and terminal-throws calls, and it also
omits `HUnsafeBlock` and the literal-condition folding used elsewhere.

Those are not merely cases the checker cannot prove. The phase-2 checker
already has richer terminal-flow semantics at
`lang/driftc/checker/__init__.py:4179-4343`:

- `HUnsafeBlock` delegates to its body;
- literal `if true` / `if false` selects the reachable branch;
- `HTry` is terminal when its body and every catch arm are terminal;
- a loop without a reachable loop-local `break` is terminal;
- resolved terminal-`throws` calls are terminal;
- statement-form matches are terminal when every arm is terminal.

Consequently the new guard still rejects valid non-returning `-> Int` lambdas
for these forms. That preserves the same no-semantic-masking violation, just
behind a wider whitelist. The comment calling this "semantic no-fallthrough
analysis" is therefore stronger than the implementation.

Do not grow a second terminal-form list locally. Extract/share one flow
authority with the phase-2 checker, with enough result information to
distinguish fallthrough, valued return, bare return, and divergence. A bare
`return;` in a non-Void lambda must remain an error even though ordinary
function-level terminal analysis correctly calls it terminal.

Required boundary pins should include at least the source-reachable omitted
forms: all-terminal try/catch, unsafe terminal block, non-breaking loop (or the
existing literal-true-loop desugaring), and a terminal-`throws` tail call. Keep
a fallthrough negative and a bare-return negative.

## P1 — the throw-effect root cause remains non-conservative and the two copies are already out of parity

The checker walker at `lang/driftc/type_checker.py:4664-4819` still returns
`False` for source HIR wrappers whose children can throw:

- `HMapLiteral` keys/values;
- `HFString` holes;
- `HExceptionInit` positional/keyword field values when the constructed error
  is first stored or otherwise used as a value;
- keyword arguments on `HCall`, `HInvoke`, and `HMethodCall` (the three call
  cases inspect only `.args`).

These have the same consequence as the fixed match/block omissions: a lambda
whose only escaping throw is below one of these wrappers records
`can_throw_effective=False`; strict stage2 trusts that mark and emits a plain
call, so an actual throw can again abort instead of reaching error dispatch.
`HMapLiteral` is especially direct evidence of drift: stage2 already descends
it at `hir_to_mir.py:5482-5483`, while the checker authority does not.

The newly claimed stage2 parity is also incomplete. The checker adds
`HBorrow` descent at `type_checker.py:4764-4765`, but the fallback walker falls
through at `hir_to_mir.py:5497`. Both copies omit keyword arguments and the
other wrappers above.

There is also a function-boundary error in both walkers. A standalone nested
`HLambda` is recursively classified (`type_checker.py:4723-4724`,
`hir_to_mir.py:5457-5458`), so merely constructing or passing a throwing
lambda makes the enclosing lambda appear to throw. Direct IIFEs are already
handled by the preceding `HCall(fn=HLambda)` / `HInvoke(callee=HLambda)`
branches; an uninvoked nested lambda must be a traversal boundary.

This bug was caused by incomplete duplicated tree walkers, and the submitted
fix extends both lists while they remain inconsistent. Close the root by
using one exhaustive, boundary-aware HIR effect traversal shared through an
injected CallInfo lookup/predicate, or an equivalently centralized authority.
Every HExpr/HStmt variant must be deliberately recursive, handled specially,
or declared a leaf; unknown new variants should fail conservatively in the
checker-facing path rather than silently mean nothrow.

## P1 — the tests do not pin the broader effect fix claimed in `PROGRESS.md`

The new positives in
`lang/tests/driver/test_stored_capturing_lambda_diagnostic.py:84-153` cover
fully divergent `HIf`, `HMatchExpr`, and nested `HBlock`. They are good pins
for the original reproductions, but the match test couples two changes: every
arm throws, so it exercises both `_block_diverges` and `_lambda_can_throw`.

`PROGRESS.md` correctly notes that the effect bug is broader than divergent
bodies, then provides no regression for that broader behavior. Add a
value-producing match with one throwing arm and one normal value arm, execute
both arms under the proper try/catch boundary, and assert the normal value as
well as caught-error behavior. That isolates the throw-effect walker from the
value-less-body guard.

The patch also claims/fixes `HCast`, `HBorrow`, and `HUnsafeBlock` traversal
without a direct regression for any of them. For every source-reachable case
retained in the fix, establish the pre-fix red behavior and add a full
compile/run pin. The exhaustive-walker closure above also needs at least one
pin through a previously unvisited value wrapper (map, f-string, exception
initializer, or keyword argument) and a nested-lambda-boundary negative/positive
pair proving that construction does not execute the nested body while an IIFE
does.

## P2 — progress wording/status should be corrected with the next revision

Until the above closes, `PROGRESS.md` should not describe `_block_diverges` as
semantic no-fallthrough analysis or the stage2 additions as parity, and the
finding should remain open. The targeted 51/51 result is useful but does not
exercise the still-missing branches identified above.
