## P1 — R4.4 migration left a contradictory Phase 5 positive

`test_phase5_result_ok_payload_duplicates` expects this source to compile:

```drift
fn make_ok(a: core.ConstArc<String>) throws -> core.ConstArc<String> {
	val n = use_arc(a);
	return Ok(a);
}
```

R4.4 deliberately made exactly this shape a clean rejection: source
`return Ok(value)` becomes `HReturn(HResultOk(value))`; `HResultOk` types as
internal `FnResult`, while the declared surface return is the user payload.
Allowing it through reaches stage2, which lowers the inner `HResultOk` to
`ConstructResultOk` and then wraps the return into another
`ConstructResultOk`. The prior review accepted clean rejection instead of the
certified tree's payload-mismatch ICE.

The full-suite positive was not migrated when that contract changed. This is
causally part of the same return-authority patch and reopens the parent.

Do not merely change this positive into another rejection or delete its Phase 5
coverage. Its stated contract is distinct: a non-Copy `ConstShare` value in an
`HResultOk.value` owned slot must receive the real implicit `const_share()` HIR
wrapper, with no unconsumed suppression mark. Preserve that internal boundary
coverage in a synthetic-HIR structural test if `HResultOk` remains an internal
node. The replacement should inspect the rewritten payload/call side tables or
otherwise prove the wrap directly; a generic `rc == 0` assertion is weaker than
the existing claim.

Also preserve the existing real-source `return Ok(5)` negative and the stub
pipeline's clean-diagnostic/no-crash pin until the source contract is resolved.
Do not add an `HResultOk` exemption to `_type_return_value`: that would restore
the double-wrap path already shown to be unlowerable.

Editing the existing Phase 5 test requires Slawomir's explicit approval under
the repository rule. The implementer should propose the exact replacement test
before editing it.
