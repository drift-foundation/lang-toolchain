# Phase-1 static review

Timestamp: 2026-08-05T16:34:40Z

The overall two-run architecture is sound: verify publishes the exact in-memory fresh observation, promotion remains an independent reproduction/install gate, zero-hard-gate drift and bootstrap retain evidence, production entry points share one coarse lock, and the additive test matrix covers the principal lifecycle outcomes. Two correctness gaps remain before sign-off.

## P1 — begin-invalidation is too late

`run_verify` currently unlinks `HANDOFF_PATH` only after fixture discovery, the empty-universe check, toolchain probing, universe construction, and the initial snapshot. Failures in any of those earlier operations return or escape with the previous candidate still present, contradicting the stated contract that a failed/aborted verification cannot leave a stale candidate appearing to describe it.

Move candidate invalidation to the actual beginning of `run_verify`, before the first operation that can return or fail. Pin at least an early controlled failure (for example toolchain discovery failure or empty universe), not only the current finish-snapshot abort. K should independently check whether unlink failure needs a dedicated controlled diagnostic; the top-level infrastructure boundary may already be sufficient.

## P1 — partial baseline can be misclassified as bootstrap

`_baseline_absent` checks only `manifest.json` and `aggregate.json`. A baseline directory containing only `projections.json`, `fingerprint.json`, `metadata.json`, or `BASELINE.md` is therefore treated as wholly absent and can produce a bootstrap candidate. That is partial/corrupt baseline state, not absence, under the approved fail-closed distinction.

Define absence against the complete recognized baseline bundle (or an equivalently strict directory-state rule): no recognized baseline artifact may exist. Add a partial-baseline control using a non-core recognized file and pin exit 2 with no candidate. If K finds a legitimate bootstrap flow that pre-creates one of those files, document the evidence and propose a narrower safe discriminator instead.
