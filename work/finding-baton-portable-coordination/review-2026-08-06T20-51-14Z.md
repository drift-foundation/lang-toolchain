## P1 — the post-claim seam is still after delivery

`wait_for_message.try_claim()` at `tools/baton/baton_v6.py:2645-2652` commits the claim, calls `_delivery()`, and only then invokes `_fault("wait:claimed")`. Consequently `test_gate_after_claim_still_delivers` gates after all content has already been fetched and cannot prove the property requested in the prior review: an instance transition between claim commit and content fetch must not strand the claim.

Move or split the seam so the deterministic hook fires immediately after `store.claim()` returns and before `_delivery(store, claim)`, while the same Store remains open. The existing gate test should then prove that `_delivery()` still reads and returns the byte-exact body through that already-open authority. If a second post-delivery seam is useful for another crash boundary, give it a distinct name rather than weakening the post-claim seam.

## P1 — doctor still does not validate transition attribution

The doctor query at `tools/baton/baton_v6.py:2790` selects only entity/state/verb. It checks that the verb belongs to a broad set, but never examines `op_id`, `participant`, `actor`, `seed`, or `at_ts`. That does not close the prior requirement to validate attribution fields and flag malformed/unexplained transitions. A schema-valid row with a valid edge and verb but a malformed actor/seed/op id currently passes.

Validate the stored attribution against the protocol grammars and required presence/shape, and validate any edge/verb relationships that are part of the transaction contract. Add at least one forged-attribution pin whose state chain and tail remain otherwise valid, so the failure cannot be credited to another ledger check. Keep the implementation proportional: this is integrity diagnosis, not a second semantic transaction engine.

## P1 — two T8 timing tests still do not prove their named boundaries

`test_wal_reset_while_blocked_still_wakes` uses a 0.4-second sleep rather than the existing `wait:armed` seam. It can checkpoint before or after the intended blocked interval depending on scheduling. Synchronize the churn thread from the arm seam (or an equivalent event/barrier), then reset WAL while the waiter is demonstrably armed and blocked.

`test_degraded_sleep_receives_configured_interval` passes interval 7.5 with timeout 0.5, so production correctly sleeps only the 0.5-second deadline remainder. Its disjunctive assertion accepts that value and therefore never proves the configured rescan interval reaches `sleep()`. Use a deterministic clock/sleep seam or publish during the first degraded sleep so the recorded call is exactly the configured interval without making the test slow.

The raw decoder/mask matrix itself is now real. The validated-reopen count assertion is weaker than its name because `try_claim()` reopens after every poll result, but it is not a blocker if the intended design is explicitly “every event prompts a validated requery.” In that case simplify/clarify `_InotifyWatch.poll()`'s unconditional `flags["relevant"] = ... or True`; otherwise make `relevant` affect control flow and pin both paths.

This leaves a declared public config field with no behavior and makes the claimed configured projection inventory incomplete.

Choose one current contract before packaging: either use the configured prefix consistently for materialization/inventory (including shared-directory participant cases), or remove the unsupported field from the strict config schema/example. Pin a non-default prefix or its rejection. Do not carry a dead compatibility-shaped field into the standalone package.
