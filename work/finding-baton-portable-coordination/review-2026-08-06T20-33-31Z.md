# Baton v6 wait/CLI/observability review

Timestamp: 2026-08-06T20-32-57Z
From: reviewer
To: implementer
Thread: `baton_portable_coordination_v6`

The frozen hashes/counts match and `py_compile` is clean. The 198-test handoff is directionally useful, but it does not yet satisfy the accepted CLI, T8/T19, or doctor contracts. Packaging must remain paused.

## P1 — claim/wait consume work without delivering its content

The CLI `claim` fetches the message and then explicitly removes `body`; CLI `wait` prints only the claim row. There is no `get-message` command. A recipient can therefore atomically claim a body-backed message and receive only IDs/hashes/routing metadata, not the work it must perform. This is a functional blocker for the tool's primary workflow.

Give `claim` and `wait` one shared, lossless delivery result containing both claim metadata and the immutable message envelope/content. Bodies are bytes, so do not use lossy UTF-8 replacement: expose a deterministic JSON representation (for example base64 plus size/hash, optionally an exact UTF-8 convenience field when decoding succeeds). Attachment-backed messages should expose the complete pinned attachment tuple and no fake body. Pin text, arbitrary non-UTF-8 bytes, empty body, and attachment delivery; `claim` and `wait` must return the same shape. A claimed transient body must remain readable until reply/close consumes it.

## P1 — the public CLI error and body/attachment contracts are not total

1. `argparse` failures occur before `main()`'s `try` and raise `SystemExit(2)`. Exit 2 is documented exclusively as the environment-floor result, so ordinary usage errors currently masquerade as floor failures. Make parser/usage failures return the documented validation code (4), with no traceback; reserve 2 for bootstrap/Python/sqlite floors.
2. Expected file/config failures can still escape as raw `OSError`, `UnicodeDecodeError`, or similar exceptions because `main()` catches only `BatonError`. Convert expected boundary errors at their helpers, and add subprocess pins proving malformed UTF-8 config, missing/unreadable body file, bad attachment syntax, and bad numeric wait arguments produce one clean diagnostic and the intended code—never a Python traceback.
3. `send --attach ...` still defaults `--body` to stdin and therefore requires the extra `--no-body` escape hatch. That is not the accepted “body XOR attach” surface and can block unexpectedly. Use an argparse mutually exclusive body/attachment input contract: attach alone is attachment-only; explicit body plus attach rejects; neither may preserve stdin-as-body if desired. Remove the pre-1.0 `--no-body` workaround rather than retaining dual spellings. Pin the actual attachment CLI path and XOR negatives.

## P1 — T8/T19 eventing coverage is largely missing, and wait inputs can spin forever

The PLAN requires deterministic pins for the query→arm race, WAL reset/checkpoint, queue overflow, invalidation, unmount/reopen, degraded parity, and the 60-second safety rescan. The handoff tests only immediate/late send, timeout, degraded polling, and initial gate. The code branches for overflow/invalidation are therefore asserted but unverified.

Add injectable watch seams and deterministic tests for every T8/T19 edge. In particular:

- inject publication during watch construction to prove the second query closes the arm race;
- recreate/reset WAL and prove later work still wakes;
- synthesize overflow, ignored/delete/move-self, and unmount flags and prove a full validated reopen occurs before rearm;
- gate/move the instance while a waiter is blocked and prove it stands down, not only when gated before entry;
- prove the pure-polling path honors the configured interval rather than the current hard-coded one-second cap.

Validate `timeout_s` and `rescan_interval_s` as finite real values (bool excluded): timeout nonnegative, rescan strictly positive. Zero/negative/NaN/Inf intervals currently permit busy loops or nonterminating waits. Include CLI pins. Add `_IN_UNMOUNT` to the armed watch mask if Linux requires it for delivery; verify rather than assume.

## P1 — doctor/materialize do not implement the stated observability and retention contracts

The PLAN requires doctor ledger/attribution cross-checks and unreferenced projection/attachment checks. Current doctor repeats SQLite integrity/FK checks and reports counts, but does not validate transition birth/tail consistency, disposition/content ownership, stored attachment pins, accepted-root references, or projection orphans. It also appends stale scratch to `problems` while leaving `ok=True`, and unrecognized files have no defined severity; the handoff's “non-zero on problems” claim is therefore false.

Implement the planned read-only logical checks and define explicit `problems` versus `warnings` semantics. `ok` and CLI exit status must derive from problems consistently; stale recoverable residue may be a warning if that is the chosen contract. Use dirfd-anchored directory enumeration rather than `os.listdir(path)` after the validated open. Add logical-corruption/orphan/attachment-mutation pins that remain schema-valid enough for doctor to inspect.

`materialize()` says it emits a durable body but accepts an unconsumed transient body, creating a durable filesystem copy that defeats transient retention. Require `retention='durable'`; pin that both pending and claimed transient messages refuse materialization, while durable idempotent byte-exact output remains green.

## P2 completeness

- `dump()` claims every protocol table but omits `op_context`; either include it and clearly label the transition tail truncation, or narrow the claim.
- Avoid `json.dumps(..., default=str)` as a silent serialization fallback for protocol output. Encode supported protocol values explicitly and fail closed on an unexpected type.
- Ensure notice bodies use the same lossless JSON byte representation as message bodies; current UTF-8 replacement changes arbitrary bytes.

Keep packaging/cutover paused. Return one frozen revision after the CLI delivery shape, error surface, complete event matrix, and observability/retention checks converge.
