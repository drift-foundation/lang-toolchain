The frozen hashes and line counts match the handoff, `py_compile` is clean, and the focused suite exits successfully. The source/bound-destination role split fixes the original pre-bind fork, and the guarded metadata, held-fd source read, resumable publication, and migrate audit are material improvements. This revision is not ready to sign off because the same fork remains possible after destination binding, and the required committed-boundary recovery matrix is still absent.

## P1 — a bound destination copy can still be cloned and activated more than once

`move_bind_destination()` proves physical location only while changing the copied DB to `move_role='destination'`. `move_activate()` then trusts that inherited role and token without revalidating that the open store is still at `move_peer`. A copy or rename after binding therefore carries the destination role and can activate anywhere.

Independent repro against the frozen pair:

1. enter/copy/bind at the one declared destination;
2. checkpoint the bound copy, then copy its config and DB to a rogue directory;
3. call `move_activate()` once on the bound path and once on the rogue path with the same token.

Observed result: `post_bind_copies_activated ['bound', 'rogue']`.

This is the same multiple-authority failure as the first review, just one state transition later. The headline test copies its rogue **before** binding, so it never exercises the dangerous `destination`-role clone.

Activation must revalidate the exact canonical bound config path and its no-follow parent identity before committing. A post-bind rogue/renamed copy must refuse activation. Apply the same route validation before returning an idempotent `move_bind_destination()` success; its current committed fast path also accepts a cloned bound DB from another path.

Add a red-first post-bind-clone test that attempts the rogue activation before activating the real destination, then proves only the exact bound path becomes writable.

## P1 — completed-token history does not retain or validate routing

The clarification required post-bind/post-activation discovery from immutable token/UUID/**peer** history. `ceremonies` stores the token but no peer. Activation clears `move_peer`, so its committed retry can validate only `token + status='none'`, not the route. Decommission retains the route in `instance_meta`, but its committed fast path returns before comparing the caller's `moved_to`.

Independent repro after a completed move:

`move_decommission(source, token=token, moved_to='/.../wrong/baton.json')`

returns `{'already_committed': True, 'moved_to': '<original destination>'}` instead of rejecting the mismatched retry.

Retain the canonical destination in immutable move history (for example a ceremony peer/routing column or a dedicated move-history row) and validate UUID/token/operation/route on every committed fast path. At minimum pin:

- bind retry from a cloned/wrong path rejects;
- activation exact retry at the original route succeeds, while a copied/renamed route rejects;
- decommission exact retry with the original `moved_to` succeeds, while the same token plus a different `moved_to` rejects;
- `move_copy()` post-activation stage discovery validates the retained peer rather than token+UUID alone.

## P1 — T15 still lacks the promised committed-boundary crash/restart proof

The subprocess matrix covers only the four `move_copy()` fault points. The previous review explicitly required restart/resume at source binding, destination-role commit, activation commit, and decommission commit as well. Ordinary same-process calls after a returned success are useful idempotence pins, but they do not test the lost-response crash window.

Add post-COMMIT/pre-return fault hooks and fresh-process recovery pins for:

- `maintenance_enter(move=True)` source binding (the committed token/state must be discoverable and the same move resumable);
- `move_bind_destination()`;
- `move_activate()`;
- `move_decommission()`.

Each retry must either return the matching committed result or expose the documented safe recovery path, with no manual artifact deletion and no second active authority.

## P1 — copying the database is unbounded and quadratic in memory

`move_copy()` builds `db_bytes` with repeated `db_bytes += chunk`, then `_publish_bytes_at()` writes the accumulated object. Mailbox size is not bounded, so moving a multi-gigabyte durable store can consume multiple gigabytes and repeated immutable-byte concatenation makes the copy quadratic. That is not acceptable for the portable standalone tool this implementation is intended to become.

Stream the held source fd into the scratch destination in bounded chunks while hashing, fsync it, and no-clobber publish it. Resume may hash/validate an existing regular destination against a streaming source hash; it must not materialize the DB in RAM. Treat premature EOF and `os.write()` returning zero as fail-closed errors. Open existing destination artifacts nonblocking/no-follow and require regular files before hashing so a FIFO/device cannot hang or impersonate a resumable artifact. Add a bounded-memory/short-write pin around the streaming helper rather than allocating a giant fixture.

## P2 hardening

`move_copy()` currently treats every non-`EXIT_DAMAGE` `BatonError` from destination stage discovery as “no complete pair.” Narrow that recovery classification to the expected absent/incomplete states. A protocol/config/gate error from an existing pair should not be silently reinterpreted as absence; it should fail closed with the underlying reason or an explicit unexplained-artifact diagnostic.

Keep wait/CLI paused. The role model is now close, but sign-off requires the post-bind authority repro, immutable route validation, the full committed-boundary crash matrix, and streaming copy semantics.
