Phase-1 review is directionally clear, but four contract gaps need a second design pass before Slawomir's rulings.

P1 — Detail bytes do not prove root-binding identity. If two configs map language.design to two clones containing the same target bytes, sha256+size passes while the reviewer reads adjacent context and writes the default response in the wrong tree. Hashes therefore do not subsume configuration/root generation. Compare at least: (a) one authoritative config per mailbox, changed only while doctor --assert-empty; (b) a collision-resistant root binding ID in every config entry and envelope; or another mechanism that proves location authority without placing absolute paths in envelopes.

P1 — Re-evaluate the claim that separate configs sharing one mailbox are required. Cross-tree use works with one explicitly passed mailbox config containing all participants and roots, regardless of which tree contains the Baton launcher. One config is substantially easier to make coherent. If multiple configs are retained, specify how participant declarations, root bindings, config revisions, and mailbox policy are proven equivalent; a content hash is insufficient.

P1 — Receipt/state identity is internally contradictory. Keying receipts by mailbox ID plus canonical-path hash does not survive a mailbox move; keying only by a copyable human label can collide if a mailbox is copied. Separate a human mailbox name from a generated collision-resistant mailbox UUID and propose exact move/copy semantics. Also distinguish the v5 tmpwatch defect from process-death recovery: durable receipts prevent accidental /tmp loss while an instance lives, but a per-live-instance seed lost at reboot still cannot legitimately close the claim. Consider making the receipt/state directory an explicit absolute config field rather than introducing a new implicit XDG authority.

P1 — Decide whether config revision is a first-class stamp property. A mailbox UUID proves which transport was opened, not that active participants use the same participant/root/policy mapping. A clean design may require config generation in config+mailbox stamp with changes allowed only when the mailbox is assert-empty.

P2 — A warning for a known network filesystem may be too weak because atomic no-clobber rename is Baton's exclusive-claim authority. State whether unsupported filesystem types fail closed; capability checks and the 60-second inotify fallback need separate treatment.

P2 — Keep doctor orphan reporting conservative. A detail-prefix/age heuristic cannot establish that an unreferenced file is an orphan and must never authorize removal.
