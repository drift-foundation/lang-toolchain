The frozen hashes/counts match, `py_compile` is clean, and the 184-test suite independently exits green. The same-directory gate and binding-consumer audit are sound. Two narrowly scoped boundary omissions remain before the move slice can be signed off.

## P1 — post-publication “full validation” omits destination identity

The existing-pair stage-discovery path now calls `_validate_route_identity()` before every stage return. The first-publication path does not: after closing the held destination dirfd, it reopens `dest_config` and checks only `{uuid, move_token}` before returning `stage='copied'`.

A destination-directory substitution between `_fault('move:db-copied')` and that final open can therefore make `move_copy()` report success for a same-UUID/token copy at an unbound inode, despite the new immutable identity contract. Call the same binding destination validator on `check` before accepting the final pair, and cross-check its live mirrors/role as appropriate. Add a fault-hook pin that substitutes the destination after publication but before final validation and proves failure; restoring the original directory must allow resume.

## P1 — the move-copy source config re-open is not type-checked

`_read_config_at()` and the existing-destination publisher now use nonblocking/no-follow plus `S_ISREG`, but `move_copy()`'s source-config re-read opens nonblocking/no-follow and then reads to EOF without `fstat(...).S_ISREG`. If the pathname is replaced after the Store's initial validated open, a device or other non-regular file can still be consumed by the unbounded `config_bytes += chunk` loop (for example, a non-terminating source can exhaust memory) instead of failing closed.

Require the re-opened source config fd to be regular before reading. Pin a replacement with a FIFO/device-like non-regular node through the existing post-open fault seam; it must reject promptly with the regular-file diagnostic and leave the move gated/resumable. Also translate an existing destination symlink/open failure in `_publish_bytes_at()` into the normal `BatonError(EXIT_DAMAGE)` surface rather than leaking raw `OSError` once CLI consumes this helper.

With those two checks and the full move matrix green, the maintenance/move/migrate slice is ready for sign-off and work may proceed to wait/CLI.
