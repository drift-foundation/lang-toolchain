# Baton v6 wait/CLI/observability round-2 review

Thread: `baton_portable_coordination_v6`

The frozen hashes/counts match and `py_compile` is clean. The lossless JSON representation, parser exit mapping, body/attachment CLI, transient materialization guard, and anchored inventory are sound improvements. Four contract gaps remain.

## P1 — wait claims first, then reopens to deliver

`wait_for_message()` still returns only a claim row. CLI `wait` then closes that Store, reopens the instance read-only, and calls `_delivery()`. A maintenance/move gate, directory transition, or authorized claim recovery in that window can make the CLI fail after it has already committed the claim, leaving the recipient with neither the message nor an unclaimed retry.

Build the lossless delivery while the same validated Store that committed the claim is still open, and return that delivery from the wait path. CLI claim and wait should consume that one result directly; do not reconstruct delivery through a second instance open. Add a deterministic post-claim/pre-return seam that gates or invalidates the pathname and proves the already-claimed content is still returned byte-exactly. Recovery can occur later, after the consumer has actually received its claim identity and content.

While doing this, verify body integrity before emitting it: recompute size/hash and compare with the message/content metadata. `_body_repr()` currently trusts the supplied stored hash without proving it describes the bytes. A schema-valid content/hash mismatch must fail as damage, not be delivered with contradictory metadata.

## P1 — accepted-root authority is still directly mutable

The new doctor test demonstrates the deeper bug by executing `DELETE FROM accepted_roots` successfully outside any operation context. `accepted_roots` is the attachment-resolution authority and is supposed to change only with config acceptance; doctor detection after an unauthorized committed mutation is not sufficient.

Add insert/update/delete guards allowing only regen (bootstrap inserts occur before triggers, as init already documents). Keep the doctor coherence check as defense in depth. Rewrite the corruption test through an explicit test-only corruption construction that does not normalize direct production mutation as supported behavior. Pin uncontextual and non-regen contextual INSERT/UPDATE/DELETE refusals, plus a real regen success.

## P1 — doctor does not validate the audit chain or attachment bytes

“Ledger birth consistency” currently means only “at least one NULL-from transition exists.” It does not catch duplicate births, broken from→to chains, or a latest transition whose state disagrees with the live message/claim. The accepted PLAN calls for ledger/attribution cross-checks.

For each retained message and claim, validate exactly one birth, contiguous transition order, legal edges, and tail state equal to the live row; validate transition attribution fields and flag unexplained/malformed transitions. Account explicitly for GC'd subjects whose permanent ledger legitimately has no live row. Add schema-valid forged-transition pins for duplicate birth, broken chain, and wrong tail.

For attachments, doctor checks root/generation metadata but never calls the existing `verify_attachment()` or otherwise hashes the live file. A mutated attachment therefore reports healthy. Verify every retained attachment's pinned path/size/hash through the existing no-follow authority and report mutation/unreadable paths as problems. Add an actual post-publication mutation pin.

Also check each `contents` row's recorded size/hash against its bytes and enforce the per-owner invariant (exactly one owning message/disposition/notice, not merely “not orphaned”). Delivery and doctor should agree on corruption.

## P1 — the claimed T8/T19 edge matrix does not exercise the named events

`test_synthesized_disruption_forces_validated_reopen` parameterizes `flag_name`, but never uses it. Every case returns the same hand-written `{'revalidate': True}` object, so overflow, ignored, move-self, and unmount parsing/masking are not tested. The WAL test checkpoints before arming the waiter, not while it is blocked. No test proves the degraded path's actual sleep interval.

Extract or inject the event decoder so raw synthetic inotify records for each exact mask drive `_InotifyWatch.poll()`, and use those decoded results in the waiter/reopen tests. Assert the armed mask contains the required bits. Reset/checkpoint WAL after the waiter is armed, then publish. Instrument degraded `sleep()` to prove it receives the configured interval. These should be deterministic unit tests; no privileged real unmount is required.

## P2 completion

- The accepted PLAN also names unreferenced projection checks. `doctor()` currently treats every non-instance file as a generic warning and never reconciles configured projection directories/prefixes against durable messages. Implement the planned projection-orphan inventory or explicitly narrow/update the plan before sign-off; do not silently omit it.
- `_to_jsonable()` should require string dict keys rather than silently `str()`-coercing them, and reject non-finite floats so it cannot emit non-standard `NaN`/`Infinity` JSON.

Packaging/cutover remains paused. Return one frozen revision after atomic wait delivery, root guards, full audit/content/attachment checks, and a real event decoder matrix converge.
