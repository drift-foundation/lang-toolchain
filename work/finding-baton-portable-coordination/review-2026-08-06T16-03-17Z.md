Round 14 correctly removes both residual dual-authority defects, and the consolidated plan is materially easier to implement and review. These final plan deltas are required before asking Slawomir for implementation authorization.

1. **P1 — extraction-ready Baton is now an explicit user requirement.** After v6 receives field use it will move from drift-lang into its own repository. Nothing under `tools/baton/` may depend semantically on Drift, drift-lang, `work/`, `finding-*`, compiler releases, AGENTS workflow, or Drift participant names. This includes implementation, tests, schemas, example configs, README, zipapp metadata, and manifest. Use neutral multi-workspace fixtures and addresses. Drift’s active config, finding projection policy, participant declarations, cutover instructions, and AGENTS integration remain outside the reusable package. The eventual extraction should require path/build changes, not semantic edits.

2. **P1 — the approved dirfd/no-follow boundary must cover the SQLite authority itself.** The consolidated plan lists config/roots/attachments/projections but omits the DB. Python `sqlite3.connect()` does not expose `SQLITE_OPEN_NOFOLLOW`; do not silently weaken the ruling by opening an unchecked path. Research and pin a concrete Linux-safe open. A promising locally probed shape is: open the instance directory with `O_DIRECTORY|O_NOFOLLOW`; open the existing DB relative to that dirfd with `O_NOFOLLOW` (init uses `O_CREAT|O_EXCL`, operational open must use existing-only); connect with URI `file:/proc/self/fd/<fd>?mode=rw`; verify the opened DB identity/canonical location and directory/inode invariants. On this host SQLite canonicalized that URI to the expected DB and created WAL/SHM beside it. This is evidence, not a prescribed answer—challenge it if SQLite reopening/canonicalization or sidecar handling leaves a race. Whatever approach is chosen needs symlink-swap, missing-DB-no-autocreate, wrong-inode, sidecar-location, and init-no-clobber tests. If stdlib SQLite cannot meet the approved boundary, stop for Slawomir rather than substituting ordinary pathname validation.

3. **P1 — restore the full connection/durability contract to the consolidated plan.** It currently omits the operational PRAGMAs established in round 11. Init must establish WAL deliberately; every connection must set/verify the applicable contract before protocol work: `journal_mode=WAL`, `synchronous=FULL`, `foreign_keys=ON`, bounded `busy_timeout`, and the chosen safe-schema settings (for example `trusted_schema=OFF` if compatible with the static triggers). Use existing-only open outside init so a typo cannot create an empty database. Define read-only/doctor connection behavior and make schema/integrity validation precede mutation. Pin reopen verification and refusal when persistent mode/schema invariants differ. Clarify that “transient scrub” is protocol retention, not guaranteed forensic erasure from SQLite pages/WAL unless that stronger promise is intentionally implemented.

4. **P2 — ledger creation events and state lifecycle need explicit triggers.** The plan says AFTER-UPDATE triggers, but a pending message and active claim are born by INSERT. Add insert-ledger triggers (NULL→pending, NULL→active or an equivalent event vocabulary) so the permanent audit has no unexplained first state. Keep actor/seed/op attribution from the same transaction context. Pin that a direct context-bearing INSERT is logged and an uncontextual INSERT/UPDATE state mutation fails closed. Also state which transient terminal metadata GC events are represented in the ledger before their rows disappear.

5. **P2 — retain the move proof in the consolidated tests.** In addition to “at most one active,” test restart/resume at every source/destination boundary, idempotent destination activation/source decommission by exact token, and refusal to abort a move unless the named destination remains gated or is attestably destroyed. A copied DB with the same UUID must never be independently clearable through the generic stale-maintenance ceremony.

After incorporating these, keep `PLAN.md` as the sole implementation source and mark older rounds historical. No implementation is authorized by this review.
