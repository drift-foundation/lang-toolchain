## P1 findings

1. **The claimed v5 response-retention parity is incomplete.** `reply(..., retention=...)` applies an override on the first commit, but `_verify_retry()` does not compare retention. Empirical probe: first reply committed `durable`, retry supplied `transient`, and returned `already_committed=True`. More directly, `close_claim()` has no `retention` parameter at all, despite the handoff claiming the override was preserved for reply/close. Therefore transient→durable close still drops the close body, and durable→transient close still retains it.

   Add disposition retention as an explicit immutable/idempotence field (or another unambiguous authority). Reply retry must compare the requested effective retention with the committed outgoing message; close must accept the same optional override/default-inherit surface as v5, use it to decide retained body versus hash-only identity, and compare it on retry. Pin inherit, both override directions, post-commit mismatch, close body lifetime, and invalid retention for both operations.

2. **Notice early-expiry does not authenticate the exact author instance.** `notices` records only `from_participant`; `expire()` authorizes a live notice when that participant string matches. Any other actor under the same agent participant can delete it. Probe: `probe.sender/author1` published; `probe.sender/author2` successfully early-expired it. The reviewed v6 rule inherited from v5 was exact author actor+seed verification, with dead-author cleanup requiring human recovery.

   Store immutable `author_actor` and `author_seed` on the notice, set them at publication, and require exact participant+actor+seed for non-TTL early expiration. An elapsed TTL may be swept independently. Add same-participant/different-actor, same-actor/different-seed, exact-author, elapsed cleanup, dead-author recovery/reporting, and direct-SQL immutability/insert-context pins. Also restore the notice lifetime contract: v5/default protocol uses a finite TTL (currently 86,400 seconds); `ttl_seconds=None` creates immortal notices and the new test treats that as normal. Require/default a positive expiry unless Slawomir explicitly approves indefinite broadcasts.

3. **`recover_claim()` does not enforce human authorization.** It accepts any grammatical actor/seed and no configured participant. Probe: an unconfigured actor named `unconfigured` recovered a claim and produced an audit row. This contradicts the locked human-authorized recovery invariant and loses the cross-workspace participant identity in the audit.

   Define the store-level authority before CLI work: pass the recovering participant, validate it through config, require the configured singleton/human recovery class (or another explicit config capability if you can justify it), and store participant+actor+seed in `recoveries`/operation attribution. The tool is cooperative rather than cryptographically authenticated, but it must still enforce its declared workflow identities. Pin unconfigured agent, ordinary configured agent, wrong singleton actor/seed semantics, exact authorized human, and audit identity. Apply the same participant-attribution audit to other administrative ceremonies (regen/gc/move/migrate) and challenge which require human authorization.

4. **`regen` can strand or silently reinterpret live protocol objects.** It accepts any generation+1 config without checking live state or reference compatibility. Probe: publish a pending message to `probe.worker`, edit generation 2 to remove that participant, run `regen_instance()` successfully; the message becomes unclaimable because its addressee no longer exists. Attachment references have `attach_generation`, but `verify_attachment()` ignores it; a root mapping can likewise be changed under pending/permanent attachments.

   Reconcile this with the earlier reviewed regen/assert-empty rule. At minimum, participant removal/rename must be refused while any pending/claimed object names it, and root removal/remap must be refused while any retained attachment references it. Because durable messages/attachments are permanent, a blanket “no live pending work” check alone is insufficient for root mappings. Either preserve referenced participant/root mappings immutably, store versioned config/root history in the DB, or define a safe migration ceremony. `attach_generation` must become an enforced part of resolution rather than dead metadata. Add pending/claimed participant change, durable attachment root change, additive-safe change, stale open handle, and exact-next race pins.

5. **Timestamp/content coupling remains verb-name authorization rather than state coupling.** The new triggers reject uncontextual/wrong-verb edits, but any context-bearing transaction named `reply` may rewrite `completed_ts` or scrub `content_id` on an otherwise pending message without a state transition. Probe committed a pending message with `completed_ts=1999-...` and `content_id=NULL` under a `reply` context. This falsifies the claimed “coupled to terminal transitions” invariant.

   Enforce the legal row shape/edge, not just the verb label. A completion timestamp must change only in the same UPDATE that performs its allowed state edge, and scrub must be restricted to a transient message that is already terminal or becomes terminal in the consuming operation. Likewise claim `terminal_ts` must agree with active→completed/recovered. Add context-bearing-but-wrong-row/edge negatives in addition to the existing NULL-context tests.

## P2 / required-before-cutover

6. **Crash-atomic init has no crash-injection coverage yet.** The scratch→checkpoint→hardlink structure is plausible, but the three tests exercise ordinary completion/refusal only; none kills/faults the process between schema creation, checkpoint, hardlink publication, scratch unlink, and directory fsync. Add the PLAN-required deterministic fault matrix and fresh-process reopen: final absent or fully valid; never partial; post-hardlink retry reports the existing valid instance rather than damage; recognizable scratch/sidecars are reportable/cleanable under the eventual doctor contract. Check the checkpoint return tuple instead of ignoring busy/log state.

7. **Attachment snapshot/root validation needs tightening alongside regen.** Validate configured roots as canonical absolute no-follow directories at init/regen/open, not merely strings beginning with `/`. When hashing an attachment, compare pre/post `fstat` identity/size/timestamps so concurrent mutation cannot produce an ambiguous mixed snapshot. Pin a writer racing publication/claim verification. Keep the configured-root trust boundary explicit; ancestor symlink/canonical-path behavior must match the approved rule.
