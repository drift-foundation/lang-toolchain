Round 7 is close but not design-clear yet. The fixed-intent/redelivery ordering and published-before-visible proof are sound. Four corrections are required; no implementation.

P1 — terminal close/disposition is not covered. Current Drift workflow deliberately uses close to persist an immutable final review/signoff detail while emitting no outgoing PENDING token. Treating “plain close” as one unlink silently drops that contract or retains the same crash window: crash after final detail publication but before claim unlink lets retry create a second final disposition. Cover a content-bearing close with the same invariant as reply: fixed, durably persisted close intent and intermediate CLOSING (or a generalized REPLYING-to-CLOSED transaction) whose recovery redelivers/finalizes the exact already-chosen detail/outcome and never recreates it. A truly bodyless/no-disposition close may remain a validated unlink. Do not deprecate the project’s terminal-signoff path without Slawomir’s ruling.

P1 — orphan-intent GC races a live pre-REPLYING producer. Between committing transactions/<id>.json and renaming CLAIMED to REPLYING, the proposed GC predicate sees no REPLYING and no outgoing token and may delete an intent the live owner is about to reference. A matching CLAIMED named by in_reply_to makes the intent live/ambiguous, never generally GC-able. Because no atomic two-entry commit exists, either require quiescence for pre-REPLYING intent GC or let only the owning/recovery ceremony explicitly abandon it. recover-claim must account for every pre-intent naming that claim before returning it to PENDING. Update the invariant and add a concurrent GC-vs-step-2/3 test.

P1 — .tmp-<response_id> is durable recovery state, not a scratch write target. It must itself be committed from a distinct sibling scratch file using exclusive/no-follow write, file fsync, no-clobber rename to .tmp-<id>, and mailbox-dir fsync. Recovery must verify an existing .tmp’s exact bytes against the immutable intent; it must never “idempotently overwrite” it. A mismatch is damaged state and fails closed. Apply the same distinction to every transaction/tombstone artifact.

P2 — use a genuinely collision-resistant response_id and derive the address budget from the actual filesystem NAME_MAX. Twelve hex digits are only 48 bits and are too narrow for a long-lived shared mailbox. Prefer 128 random bits/32 lowercase hex, consistent with live-instance seeds; no-clobber collision remains a clean error. Recompute and test the dotted-address maximum against the longest REPLYING filename at runtime. When locating an outgoing response in any PENDING/CLAIMED/REPLYING state, parse and validate message_id/envelope identity rather than grepping a suffix substring.
