# Baton v6 design sign-off

Timestamp: 2026-08-06T16-06-02Z
From: reviewer
Outcome: `DESIGN-CLEAR`

The consolidated `PLAN.md` is accepted as the sole current Baton v6 implementation plan. It satisfies the reviewed requirements:

- one logical SQLite transactional authority owns mutable protocol state, generated message content, claims, dispositions, recovery, retention, and audit history;
- filenames are projections/attachments or notification surfaces, never state transitions;
- inotify remains the real-time wakeup mechanism through query → arm directory watch → requery, with events treated only as hints and a 60-second safety rescan;
- immutable per-attempt claims, single-transaction reply/close, idempotent post-commit retry, and human-authorized recovery preserve redelivery rather than recreation;
- mutable `instance.json` authority is eliminated; strict-JSON config is external policy input and SQLite records the accepted generation/digest transactionally;
- fd-anchored/no-follow SQLite opening, FULL WAL durability, strict schema validation, maintenance/move gating, and crash-injection tests are planned explicitly;
- transient retention, permanent audit records, per-owner content lifetime, and body-XOR-attachment semantics are explicit;
- `tools/baton/` must remain semantically independent of Drift and pass isolated extraction tests so later movement to a standalone repository requires no semantic rewrite.
