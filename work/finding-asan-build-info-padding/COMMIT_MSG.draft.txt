codegen: exempt the build-info stamp from AddressSanitizer global padding

An executable built with AddressSanitizer could not be read through the
supported interface: `drift inspect build-info <binary> --json` exited 1
with "build-info payload is not valid JSON: Extra data". The
`.drift_build_info` section contract is exactly the canonical UTF-8 JSON
document -- no magic, no framing, no length prefix, no NUL terminator --
and on a sanitized build the section instead held the valid document
followed by NUL padding, which the fail-closed reader correctly rejected.

The cause is AddressSanitizer's global instrumentation at compile time,
not the linker. ASAN rewrites an instrumented global into
`{ original, [redzone x i8] }` and carries the custom section name onto
the padded struct, so the emitted section grows past the document. The
compiler emitted the contract shape correctly; running that IR through
`-fsanitize=address` produced the padded struct and an
`@__asan_global___drift_build_info` descriptor, and the instrumented
object already measured the larger, align-32 section before any linking.
The redzone bought nothing: this stamp is pure metadata that nothing
loads at runtime, so instrumenting it added no memory-safety coverage
and only broke the byte contract.

Emit `no_sanitize_address` on the stamp global. The section name, exact
array length, `align 1`, and `@llvm.used` retention are unchanged, and
`lang/build_info.py` is untouched -- no NUL trimming, tolerance path,
compatibility reader, or second contract. The exemption is narrow: the
build-info ASAN descriptor disappears while the module's other globals
stay instrumented and the ASAN module constructor is still emitted, so
the sanitizer is not disabled. ASAN and ASAN+UBSAN were the affected
pair; standalone UBSAN was never affected.

Add `test_build_info_survives_asan_link` beside the existing normal-link
regression. It compiles with the ASAN profile signal active, links
through the real ASAN runtime archive and `-fsanitize=address -g`, reads
the linked binary through the production `extract_build_info` path, and
asserts the compiler version, ABI, and `build.profile == "asan"`. A
synthetic padded-payload test cannot reproduce a defect introduced after
the exact IR constant is emitted. The regression was observed failing
before the producer change and passing after.

Bump DRIFTC_VERSION 0.35.0 -> 0.36.0: the fix is user-visible, and before
1.0 user-visible impact bumps MINOR and resets PATCH. DRIFT_RT_ABI_VERSION
stays 22 -- one attribute on one internal metadata global changes no
exported runtime signature, cross-boundary layout, calling convention, or
ownership contract. Record the release in `doc/history.md`.

Verification: both build-info test files run whole, 63 passed, keeping the
schema, canonicalization, malformed-payload, duplicate-section, and
trailing-content negatives green; the linked-ASAN regression observed red
before the fix and green after, independently reproduced by review; and
`drift inspect build-info --json` succeeds end to end on both a normal and
an ASAN binary. Verified on clang 20.1.8; `no_sanitize_address` as a
textual global attribute requires LLVM 15 or newer.
