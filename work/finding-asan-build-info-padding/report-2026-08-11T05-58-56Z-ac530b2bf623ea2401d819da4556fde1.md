# CORE_BUG: ASAN pads `.drift_build_info`; the supported reader rejects compiler output

PushCoin independently reproduced a Drift 0.35.0 toolchain defect and has stopped broader adoption work under its regression-first policy.

## Minimal behavior

Build the same trivial app normally and with `--sanitize address`, then inspect both binaries:

```text
drift build                    --package-root "$DRIFT_PKG_ROOT" -o hello-normal
drift build --sanitize address --package-root "$DRIFT_PKG_ROOT" -o hello-asan

drift inspect build-info hello-normal --json   # exit 0
drift inspect build-info hello-asan --json
# error: build-info payload is not valid JSON: Extra data ...
# exit 1
```

The report's minimal source is a dependency-free `main` that prints `hello` and returns 0.

## Independent PushCoin evidence

- Normal Bookkeeper: inspector succeeds; section size 0x2c7, alignment 1.
- ASAN Bookkeeper: inspector fails at JSON byte 704; section size 0x380 (896), alignment 32.
- The ASAN section contains a valid 704-byte canonical JSON document followed by 192 NUL bytes.
- `lang.build_info` explicitly requires exact canonical bytes and fail-closed rejection of trailing content.
- `llvm_codegen.emit_build_info` emits an exact-length align-1 global; ASAN instrumentation/linking changes the custom section's size/alignment.

## Regression-first requirement

Please add and confirm a failing linked-binary regression before the root fix. Proposed location/name:

`lang/tests/driver/test_abi_version_stamp.py::test_build_info_survives_asan_link`

It should link the existing trivial stamped program with AddressSanitizer enabled, read it through the production `extract_build_info` path, and assert an exact valid document with ASAN profile. Then fix the sanitizer/codegen boundary and confirm normal + ASAN regressions pass.

Suspected subsystem: LLVM codegen / AddressSanitizer global instrumentation around `llvm_codegen.emit_build_info`. The preferred fix preserves the exact section contract (for example, exclude the metadata global from sanitizer padding). Do not trim NULs in the reader.

## Downstream impact

PushCoin's required ASAN instrumentation assertion is blocked: the old `--version` profile text was deliberately retired, while its supported replacement (`drift inspect build-info <binary> --json`) cannot read ASAN binaries. No app-side workaround has been approved. Steps 6–8 remain held until the regression and root fix are available on tracked `main`.
