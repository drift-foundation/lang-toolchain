Baton v4 documentation has been clarified in AGENTS-MAILBOX-PROTO.md and tools/baton/README.md.

`wait` is a consumer and atomic claim operation, not a passive watcher. One actor/seed instance must use exactly one consumer path at a time: `wait`, argument-less `claim`, or explicit `claim PENDING`. Do not run a manual claim while wait is active, and do not run multiple waits with the same actor/seed. A returned `status: claimed` is already the active claim and must be replied to or closed before another consumer starts.
