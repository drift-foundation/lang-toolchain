## Contract recommendation

Under the already-approved v1 contract, a bare stored capturing lambda is
invalid at its binding. `E-COPY-UNKNOWN` at a later alias read is downstream
noise, not an independent language error. The desired presentation is one
primary capture rejection, at the lambda/binding span.

Do **not** implement that by marking every pending lambda as diagnosed or as
guaranteed-to-fail. A captureless, fully inferable pending lambda can finalize
successfully. Suppressing its early Unknown use without resolving it risks
turning today's rejection into a silent Unknown alias/lowering hole.

The leading design is therefore to totalize pending-lambda resolution at the
first semantic value use, sharing one helper with the existing first-`HCall`,
first-`HInvoke`, and end-flush routes:

- capturing pending lambda: emit the existing v1 primary immediately, mark its
  binding as diagnosed Unknown, and remove it from pending;
- captureless lambda whose type is inferable (or receives a concrete expected
  function type): install the concrete function type, clear any cause, remove
  it from pending, then perform the ordinary Copy/value use;
- unconstrained captureless lambda: emit the existing clean cannot-infer
  primary, mark diagnosed Unknown, and remove it from pending;
- never create a `PENDING_MEANS_POISON` shortcut detached from the finalization
  result.

This is a patch hypothesis, not yet an implementation directive. The extra
probes below must establish that it preserves accepted captureless aliases and
contextual inference. If the helper cannot be shared without changing a
language contract, create a nested child finding and request Slawomir's ruling
rather than deciding silently.

## Causal-state design after those probes

For bindings that are genuinely diagnosed Unknown, the transaction-owned
binding-cause map remains sound. Direct `HLet(value=HVar(...))` propagation is
required by the confirmed alias probe. Before adding a node-level provenance
system, use the new probes to determine whether causes must also flow through a
suppressed `HCall`/`HInvoke` result into a new binding. If yes, either add an
explicit lowering-independent expression-cause authority or record a child;
do not approximate it with a descendant scan.

`HCall` and `HInvoke` must query the same exact-binding authority. All three
`make_call_ctx(...)` sites must receive a fail-toward-tripwire predicate. Cause
state must be an `_TxnDict` in `FnCheckState.OWNED_TABLES`, clear on concrete
resolution, and be covered by rollback/fingerprint/shadowing pins.

No spec or ABI change is indicated. Keep the pending unreleased version at
`0.35.0` if that remains the release state when implementation begins.
