# Preflight review 2 addendum: pending resolution must respect probe rollback

Timestamp: 2026-08-04T21:48:05Z

This augments `review-2026-08-04T21-46-28Z.md` before any implementation.

Do not implement “totalize at first semantic value use” as an unconditional
mutating hook in the generic `type_expr(HVar)` branch without first expanding
and proving the transaction boundary.

Reason: the deferred-call probe's allowlist admits expression shapes containing
`HVar`. Today that path only reads ordinary binding/pending state, so
`FnCheckState` deliberately excludes scope/binding tables. A new HVar hook that
types a pending lambda, rewrites `binding_types`, pops
`pending_lambda_by_binding`, or mutates capture metadata can run while a
`CheckerStateTxn` is open. Neither `binding_types` nor
`pending_lambda_by_binding` is currently transaction-owned, and scope maps are
also excluded. A rollback would restore diagnostics/recording tables but leak
the pending-resolution mutations.

Refine the design after tracing actual entry points:

- The current pending-callee `HCall` and `HInvoke` pre-resolution occurs in
  `type_checker.py` before entering the resolver transaction; preserve that
  property or explicitly prove otherwise.
- The confirmed `val alias = f` shape can potentially finalize at the `HLet`
  parent, before its initializer's ordinary HVar typing, using the declaration's
  expected function type if present. This is narrower than a generic HVar hook
  and avoids making every HVar a state-writing probe shape.
- Other semantic value positions (`return f`, call argument `sink(f)`, composite
  expressions) need inventory/probes. Do not claim total first-value-use
  coverage from an HLet-only patch.
- If the intended contract truly requires generic HVar finalization, either
  bring every mutated table and allocator/scope effect under the explicit owner
  or change the probe gate/context so pending-binding reads cannot execute the
  mutating route speculatively. Treat that as a real state-owner refactor, not a
  side-table exception.

Add one isolated transaction probe with a pending lambda used as a nested call
argument in a shape admitted by `_defer_probe_shape_safe`; record whether a
probe opens and whether pending/binding/capture state changes on rollback. Also
inventory `return f` and argument-position `f` before selecting HLet-only versus
general resolution.

The diagnosed-Unknown cause map itself still belongs in `FnCheckState` if it can
be written during expression typing. This addendum concerns the larger pending
lambda and binding-state mutations that the first recommendation would expose.
