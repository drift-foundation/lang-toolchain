## P1 — caused-callee suppression skips independent HCall arguments

`resolve_call_expr()` types positional arguments only inside the
`TypeKind.FUNCTION` branch.  Its new caused-Unknown callee branch returns at
`lang/driftc/checker/call_resolver.py:6831-6845` before that branch, so:

```drift
val bad = missing_receiver;
bad(missing_argument);
```

reports only `missing_receiver`; `missing_argument` is never visited.  This is
not cascade suppression—it suppresses an independent primary.  The reviewer
pin `test_caused_hcall_still_checks_independent_argument` fails with exactly
that one-message output.

Preserve ordinary argument traversal/typechecking before suppressing only the
callee-derived call-target diagnostic.  Take care not to type arguments twice
on the normal function path; a single shared argument observation is likely
safer than adding another one-off call in the suppression arm.  Add a source
pin requiring both unknown-name primaries and no call-target cascade.

## P1 — caused-receiver method suppression also skips independent arguments

The early return at `lang/driftc/checker/call_resolver.py:2275-2286` occurs
immediately after typing the receiver and before method arguments are typed.
Thus:

```drift
val bad = missing_receiver;
bad.no_such_method(missing_argument);
```

also reports only `missing_receiver`.  The reviewer pin
`test_caused_method_receiver_still_checks_independent_argument` confirms it.

Suppress only the receiver-derived method-resolution noise while retaining
normal argument traversal and independent diagnostics.  The result node may
still inherit the receiver cause after the arguments have been checked.  Pin
both primaries and the absence of a no-matching-method cascade.

## P1 — match/try were declared compound joins without cause-join producers

`_COMPOUND_JOIN_SHAPES` contains `HMatchExpr` and `HTryExpr`, so HLet correctly
stops using its broad diagnostic watermark for them.  But the only explicit
compound cause producer in the current source is the ternary join at
`type_checker.py:12318-12323`; there is no `_mark_node_unknown_cause` path for
match or try results.  Consequently even an all-caused match/try result becomes
an uncaused binding and emits downstream cascade diagnostics.

Current reviewer results:

- all-caused match: two intended unknown-name primaries, then unwanted
  `cannot copy 'joined': type 'Unknown'...` and `call target is not a function
  value`;
- all-caused try: the same four-message shape.

This contradicts the handoff claim that propagation still handles compounds.
Implement the actual reachability-aware cause joins for each advertised shape,
or narrow the declared contract if evidence shows a different correct model.
Pins should cover both sides for match and try: all reachable Unknown results
caused suppresses downstream noise; any reachable uncaused Unknown keeps the
tripwire.  Do not restore the broad HLet watermark.
