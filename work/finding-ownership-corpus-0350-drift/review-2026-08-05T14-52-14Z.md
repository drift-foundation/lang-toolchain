## Provisional interpretation, not a conclusion

The changed fixture contains an inline `core.callback0(...)` wrapping a `captures(share tr)` lambda whose body is deliberately never invoked. The source itself is unchanged from the 0.34.2 corpus baseline. The pending 0.35.0 train changed hidden/pending-lambda finalization and CallInfo/body ownership, so one fewer audited function could plausibly be removal of a previously duplicated or phantom compiler-generated function. That would be benign or desirable if confirmed from the emitted function inventory.

However, the unchanged event and site counters do not by themselves prove that explanation. An omitted real function can also leave ownership counters unchanged when that function has no counted ownership sites. Promotion therefore remains blocked until the exact missing function is identified and tied to an intended source change.
