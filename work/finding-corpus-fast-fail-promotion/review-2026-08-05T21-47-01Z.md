## P1 — the passive pin depends on a warmed, untracked runtime cache

`test_passive_fingerprint_never_builds()` assumes the real runtime archive already exists and is current, then monkeypatches both build authorities to explode. It passes in this warmed worktree but can fail when `lang/tests/tools/` is run in a clean checkout/cache, before anything has built `build/runtime_libs/...`.

Make the setup deterministic. One acceptable shape is to obtain the ordinary building fingerprint first (which deliberately establishes the verify-side artifact), then install the exploding monkeypatches, obtain the passive fingerprint, and assert the complete passive result/composite equals the building result. This both works from a cold cache and pins the currently unproven “identical composite” claim. A fully synthetic artifact setup is also fine if it exercises the real passive wiring faithfully.

There is also no need for `resolve_runtime_identity()` to import the private `_needs_rebuild` / `_runtime_deps` cache heuristics. Candidate/current equality already hashes all runtime source content (`compile_source`) and the archive bytes; changed source, ABI input, archive, environment, or tools changes the composite and rejects. Mtime-only cache staleness is not semantic identity and can falsely reject a content-identical candidate. The copied call is also not the build authority's exact contract: `build_runtime_archive()` adds `driftc_versions.py` and has a deployed/read-only acceptance branch outside `_runtime_deps`/`_needs_rebuild`.

Prefer the smaller passive rule: resolve the expected current archive path without building, require it to be a readable file, and hash it. Current snapshot equality decides staleness. If K believes build-cache freshness must remain a separate condition, extract one public nonmutating freshness authority in `lang.language_runtime` and make both build and passive routes use it, including the ABI dependency and deployed/read-only semantics; do not couple the fingerprint tool to private partial internals.

Keep the missing-artifact controlled-failure pin. Adjust “absent/stale” wording to match the selected authority.
